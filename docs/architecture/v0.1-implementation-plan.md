# v0.1 実装計画と完了状況

> 状態: v0.1.1 の実装済み計画。84 tests と Chrome 151 の permission/consent smoke を完了。PR #13 の修正前 build では foreground / background とも prompt 挿入後の自動送信 / clipboard fallback が失敗した。HEAD `5cf1416` の re-smoke では foreground の送信成功、background hidden の fail-closed、clipboard DOM copy の成功を確認した。ADR 0003 で background 自動送信の撤回と foreground-only を Accepted。安全に実行できない状態は option 5 の no-op + 明示的 feedback へ終端化する。CWS Release Gate は保留。

## 完了した実装の要点

### Step 0–1: 型、Manifest、Settings / consent

- `PendingPayload` と `Settings`、`awaitingConsent | queued | injecting` を定義しました。
- Manifest は v0.1.1、minimum Chrome 116、required `activeTab` / `contextMenus` / `scripting` / `storage`、optional `offscreen` / `clipboardWrite` / `https://chatgpt.com/*` です。
- action は設定ページを開き、設定ページは通常設定と request ID 付き preview の二つの mode を持ちます。
- preview は exact prompt、URL、selection、宛先、DOM automation / clipboard / no-retry の注意を表示します。
- UI は storage API を直接扱いません。approve button の同期 click handler が user gesture を保ったまま `chrome.permissions.request()` で optional bundle を直接要求し、要求の promise 解決後に approve runtime message を送ります。Service Worker は message を受けた後に `chrome.permissions.contains()` で `https://chatgpt.com/*`、`offscreen`、`clipboardWrite` の一式を最終確認し、不足・拒否なら pending を削除します。storage 操作は Service Worker 経由です。

### Step 2–4: X input、URL、prompt、pending

- context menu は X / Twitter の `selection` context に一項目だけ登録します。
- X DOM extractor は選択位置に近い article 内 status link を距離・DOM 順で選びます。
- URL は HTTPS、許可 host、status id を検証し、query/hash と suffix を除去します。fallback page URL も同じ normalizer を通します。
- selection は LF 化、trim、最大 8,000 UTF-16 code units です。
- 固定 prompt の動的値は sanitized URL と selection だけで、未信頼データ境界と非実行の注意を含みます。
- pending payload は `storage.session` に保存し、`expiresAt` の10分到達で論理失効させます。`alarms` は使わないため、期限到達だけで物理削除されるとは限らず、次の Service Worker 起床・関連イベント、または browser restart などで物理削除されます。終端イベントでは削除し、consent version だけを `storage.local` に保存します。旧 `openInBackground` 保存値は読み取り・使用しません。

### Step 5: State machine と tab race

- request ID ごとの Service Worker operation を直列化し、`queued` → `injecting` を `claimId` 付きで一度だけ保存します。
- consent tab は `about:blank` 作成 → `consentTabId` と state 保存 → extension settings URL 遷移です。
- ChatGPT target tab は `about:blank` を foreground で作成 → claim / `targetTabId` と state 保存 → `https://chatgpt.com/` 遷移です。読み込み中の tab 切り替え等で adapter 実行時に hidden なら、書き込み前または送信前に fail-closed します。
- v0.1.1 では `about:blank` の完了イベントを pending として保留し、目的 URL への遷移前に state 保存済みの pending を早期削除する race を修正しました。
- adapter 直前に `adapterAttemptedAt` を保存し、Service Worker restart、duplicate event、tab close、expiry でも retry しません。

### Step 6–7: ChatGPT adapter と clipboard fallback

- selector registry、isolated-world adapter、bounded MutationObserver、timeout、send button 一回操作を実装しました。
- 未ログイン、selector mismatch、timeout、send unknown、executeScript failure は offscreen clipboard write と固定 banner に終端化します。
- clipboard 失敗でも pending は残さず、既存 clipboard は読みません。banner に selection / prompt を再掲しません。
- prompt 書き込み前に visible composer の一意性を確認し、複数候補には書き込みません。click 直前にも composer / container / send control を再取得して attachment・一意性・enabled・composer 値を検証し、安全に確認できない場合は click しません。click は最大一回、retry はありません。
- adapter と clipboard の結果は、非機密の typed category / visibility / 候補数 / attachment だけをローカル開発者 console へ出力します。prompt 等のユーザーデータは含めません。

修正前の Chrome smoke では foreground / background とも `selector-mismatch`、`phase=composer`、`attempted=false`、`composer-write-unconfirmed` で終端し、clipboard fallback は `write-failed` でした。段落 plain-text 復元と単回 DOM copy を実装した HEAD `5cf1416` の re-smoke では、foreground が `status=sent`、`phase=send`、`attempted=true`、`failureReason=none`、`visibilityState=visible`、composer / send 候補各 1、全 attachment `attached` となり、メッセージ送信成功、入力欄の空、banner なしを確認しました。background hidden sample は `status=selector-mismatch`、`phase=composer`、`attempted=false`、`failureReason=composer-write-unconfirmed`、composer 候補 1・composer `attached`、container / send は `unknown`・0 で、メッセージ未送信、prompt 残留、banner 表示となりました。background clipboard fallback は `status=copied`、`failureCategory=none`、`cleanupFailureCategory=none`、`lifecycleCategory=none`、`bannerShown=true` でした。Console の visible `sent` は直前の foreground ログであり、background 成功の証拠にはしません。hidden document の React / ProseMirror state readiness は保証できず、retry / 二重送信はありませんでした。

非機密 DOM 確認では composer が contenteditable の ProseMirror `div` で、複数の直下 `p` 要素へ正規化されます。修正前の `textContent` 完全一致 gate が段落改行を保持できず、複数行 prompt の書き込み確認を誤って拒否する原因を特定したため、fail-closed と標準 `textContent` 書き込みを維持する段落 plain-text 復元を実装しました。clipboard は修正前の write rejection を、Chrome 公式例に沿った単回 DOM copy で実機確認できました。background hidden の state readiness は保証できないため、background 自動送信を撤回し foreground-only を採択しました。安全に実行できない状態は option 5 の no-op + 明示的 feedback へ終端化します。

## Step 8 の実機 smoke（foreground 成功・background hidden fail-closed）

Chrome 116 以上で、個人情報を含まないテスト文を用い、PR #13 の修正前 build を foreground / background で各一回実行しました。両経路とも prompt の視覚的挿入までは確認できたが、自動送信されず入力欄に残り、clipboard fallback は `write-failed`、固定 banner が表示されました。adapter は send 前に fail-closed し、retry / 二重送信はありませんでした。

コード修正（contenteditable ProseMirror の段落 plain-text 復元による書き込み確認、offscreen の単回 DOM copy）後の HEAD `5cf1416` を foreground / background で各一回 re-smoke しました。foreground は送信成功、background hidden は `composer-write-unconfirmed` で送信せず、clipboard fallback は `copied`、banner を表示しました。background の hidden document では React / ProseMirror state readiness を保証できないことを確認し、ADR 0003 で background 自動送信を撤回し foreground-only を採択しました。安全に実行できない状態は option 5 の no-op + 明示的 feedback へ終端化します。

残る非機密 diagnostics の確認対象は次のとおりです。

- X / Twitter の selection menu、status link、page URL fallback
- 初回 exact preview、permission grant / deny、拒否時の cleanup、同意撤回
- ChatGPT logged-in / logged-out、foreground-only の target 前面表示、旧 `openInBackground` 保存値無視
- composer / send selector、DOM 変更、timeout、書き込み確認、送信結果不明、二重送信なし
- clipboard success / failure、banner、target / consent tab close、Service Worker reload。background clipboard `copied` は確認済み

実機で問題が見つかった場合は、DOM adapter の変更を [ADR 0001](../adr/0001-experimental-chatgpt-web-handoff.md) の scope 内でレビューし、設計・Privacy・Security・CWS 文書を同期します。
