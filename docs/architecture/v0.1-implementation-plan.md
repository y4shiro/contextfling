# v0.1 実装計画

> 状態: 設計レビュー待ち。コード変更はこの文書の作成時点では行わない。  
> 対応設計: [v0.1 design](v0.1-design.md) / [ADR 0001](../adr/0001-experimental-chatgpt-web-handoff.md)

この計画は、Accepted Experimental design を小さくレビュー可能な変更へ分割する。各 step は対象ファイル、テスト、完了条件を持ち、前 step の受入条件と文書同期が確認されるまで次へ進めない。

## Step 0: 実装ゲートと型境界

**対象ファイル候補**

- `src/manifest.json`
- `src/types/`、`src/core/`
- `tests/manifest.test.ts`
- `docs/`（実装で変わった前提だけ）

**作業**

- 現行の空 permission baseline と設計上の permission matrix を再確認する。この step では機能を消費するコードがないため、Manifest に permission をまだ追加しない。
- `PendingPayload`、`Settings`、`ConsentVersion`、`awaitingConsent | queued | injecting` state の型を定義し、ブランド名を domain type に埋め込まない。
- `minimum_chrome_version` は Chrome 116 候補として実機・型・API availability を確認する。

**テストと完了条件**

- Manifest が引き続き permission 空であることと、将来追加時に no `<all_urls>`、optional host pattern を検査できる静的テスト境界。
- 実装 scope、CWS、Privacy、Security、ADR の記述が一致する。
- まだ実行可能な機能を追加しない。

## Step 1: Settings/consent page と action

**対象ファイル候補**

- `src/settings/settings.html`
- `src/settings/settings.ts`
- `src/settings/settings.css`
- `src/service-worker.ts`
- `src/manifest.json`
- `tests/consent.test.ts`

**作業**

- action click は設定画面を開く。
- 初回 preview に正規化・上限検査後の実送信 prompt、`https://chatgpt.com/`、DOM automation/clipboard のリスクを表示する。
- permission request は純粋な adapter 境界として実装し、統合フローを有効化する時点で、同意ボタンの直接 user gesture から呼ぶ。request 前に await を挟まず、要求後に `permissions.contains()` で一式を検査する。
- `consentVersion` と `openInBackground` だけを `storage.local` に保存する。

**テストと完了条件**

- preview が実際に送る正規化済み入力と一致する。
- permissions の個別 grant/deny、同意撤回、古い consent version の再 preview を検証する。
- 同意前の optional permission request と送信がない。

## Step 2: Context menu router と X selection input

**対象ファイル候補**

- `src/commands/context-menu.ts`
- `src/service-worker.ts`
- `src/sources/x/`（型、extractor、selectors）
- `tests/context-menu.test.ts`

**作業**

- `selection` context に `ChatGPTで解説する` を一項目登録する。
- callback で `selectionText`、tab id、current URL を受け、空 selection や unsupported page を拒否する。
- selector を `src/sources/x/selectors.ts` に集約し、ページ script の実行を isolated world に限定する。

**テストと完了条件**

- menu item が一項目である。
- sender、権限、対象 tab の検証と error path を確認する。
- selection text、URL、tab identifier を不要な log/保存へ出さない。

## Step 3: X URL normalizer と fixture

**対象ファイル候補**

- `src/sources/x/url.ts`
- `src/sources/x/extractor.ts`
- `src/sources/x/selectors.ts`
- `tests/fixtures/x/`、`tests/x-url.test.ts`、`tests/x-dom.test.ts`

**作業**

- 選択位置に近い article 内 status link を検出する。
- HTTPS の `x.com`/`twitter.com` status URL だけを採用し、query/hash/suffix を除去する。
- 不成功時は sanitized current page URL を許可 origin 内だけで使う。任意 URL、credentials、外部 navigation は拒否する。

**テストと完了条件**

- 親投稿、対象投稿、返信、引用、推薦投稿の fixture で最寄り対象を確認する。
- X/Twitter、query/hash、非 HTTPS、非 status、悪意ある URL、空 selection を検証する。
- fixture に実ユーザー情報、Cookie、認証情報を入れない。

## Step 4: Prompt builder と session payload

**対象ファイル候補**

- `src/handoff/prompt.ts`
- `src/state/pending-payload.ts`
- `src/storage/session-store.ts`
- `tests/prompt.test.ts`、`tests/session-store.test.ts`

**作業**

- 固定 prompt に sanitized URL と selection text だけを埋める。
- untrusted data の境界文、内部命令を実行しない旨を維持する。ファクトチェック要求、回答言語、余分な metadata を追加しない。
- preview が必要な payload は `awaitingConsent`、同意・permission 一式を確認済みの payload は `queued` として session に保存し、expiry を持たせる。履歴を作らない。

**テストと完了条件**

- exact prompt snapshot、newline/length bound、prompt injection 風入力を検証する。
- reject/success/failure/timeout/tab close/expiry で remove される。
- session 以外へ selection/URL/prompt が書かれない。

## Step 5: State machine と一度だけの claim

**対象ファイル候補**

- `src/state/state-machine.ts`
- `src/service-worker.ts`
- `tests/state-machine.test.ts`

**作業**

- request ID ごとの同一 Service Worker 内直列化を実装し、その critical section で `queued → injecting` を `claimId` 付きで一度だけ行う。storage read/write 単独を compare-and-swap とみなさない。
- 重複 context menu event、Service Worker restart、stale `injecting` を無視または expiry cleanup する。
- 自動 retry なしの terminal transition を共通化する。

**テストと完了条件**

- 同一 payload の二重イベントで adapter が一度だけ呼ばれる。
- success、permission denial、adapter error、timeout、tab close、expiry で cleanup が一度だけ行われる。
- state transition のすべてに reason と user-visible status の mapping がある。

## Step 6: ChatGPT Web adapter（実験境界）

**対象ファイル候補**

- `src/destinations/chatgpt/adapter.ts`
- `src/destinations/chatgpt/selectors.ts`
- `src/destinations/chatgpt/banner.ts`
- `src/service-worker.ts`
- `tests/chatgpt-adapter.test.ts`、`tests/fixtures/chatgpt/`

**作業**

- 同意済み `https://chatgpt.com/*` にだけ、毎回新規 ChatGPT tab を開く。
- foreground default / background setting を反映する。
- selector、input、send を一度だけ実行し、bounded MutationObserver と timeout で終了する。
- 未ログイン、DOM 変更、結果不明では retry せず clipboard fallback へ渡す。

**テストと完了条件**

- selector fixture、DOM changed、未ログイン、timeout、send result unknown を検証する。
- 既存会話 URL、Cookie、auth API、任意 host を使わない。
- DOM adapter 外へ selector が漏れず、remote code/innerHTML/eval がない。

## Step 7: Offscreen clipboard fallback

**対象ファイル候補**

- `src/offscreen/offscreen.html`
- `src/offscreen/clipboard.ts`
- `src/handoff/fallback.ts`
- `src/service-worker.ts`
- `tests/clipboard-fallback.test.ts`

**作業**

- 同意済み optional `offscreen` と `clipboardWrite` だけで static bundled offscreen document を作る。
- prompt を Clipboard API へ一度だけ書き、成功/失敗を返す。
- ChatGPT tab の小さな banner に DOM failure、clipboard success/failure、手動貼り付けの必要性を表示する。

**テストと完了条件**

- offscreen create/close、Clipboard API success、permission denial、write failure を検証する。
- offscreen から `chrome.runtime` 以外の extension API を呼ばない。
- clipboard 失敗でも payload が残らず、ユーザーへ明示される。

## Step 8: 統合検証と manual unpacked smoke

**対象ファイル候補**

- 変更済みの全 `src/`、`tests/`
- `README.md`、`CONTEXT.md`、`AGENTS.md`
- `CHROMEWEBSTORE.md`、`PRIVACY.md`、`SECURITY.md`

**作業**

- DOM fixture/unit、state transition、permission denial、clipboard failure を CI で実行する。
- Chrome 116 候補以上で unpacked extension を手動確認する。
- X logged-in/out、ChatGPT logged-in/out、foreground/background、tab close、reload、同意撤回を確認する。
- 実ユーザーの選択文、Cookie、auth、token をログ・fixture・スクリーンショットに残さない。

**完了条件**

- lint、typecheck、test、build、secret scan が通る。
- Manifest/権限、Privacy、Security、CWS 文言が実装と一致する。
- 二重送信、誤 host、履歴保存、同意回避、clipboard 失敗の残存リスクをレビューで受容または撤回する。

## Step 9: Release gate（実装後のみ）

Chrome Web Store へ提出する前に、正式名称、branding、スクリーンショット、公開 Privacy Policy URL、連絡先、CHANGELOG、CWS data disclosure、実機 Security/Privacy review、利用条件確認を完了する。この step は設計 Accepted や source repository の公開とは別であり、承認なしに提出しない。
